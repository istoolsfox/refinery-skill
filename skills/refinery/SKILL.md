# Refinery（精炼厂）——全项目代码优化引擎

一句话触发的代码优化与质量提升引擎。它不是一套孤立技巧，而是一条带闸门的流水线：
**侦察 → 定档 → 基线 → 四道工序 → 对抗自查 → 优化报告**。
深层规范按需读取，不整包加载（见文末"深层规范"）。

## 零号铁律（优先级最高）

**禁止虚编，一切断言有依有据。**

- 说"没人用"→ 必须给出全仓搜索证据（含动态调用排查，见 `reference/dead-code-evidence.md`）；
- 说"测试通过"→ 必须是你亲手运行、退出码为 0 的命令，贴在报告里；
- 说"更快/更省"→ 必须有测量数字，没有就说"理论推断，未测量"；
- 拿不准 → 标"未确认"并留给用户，绝不脑补成事实。

## 流程总览

```
第0步 侦察 Recon      → 项目身份 / 工具链 / 测试命令 / git 状态
第1步 定档 Mode       → 自有项目模式 / 上游贡献模式（别人的仓库）
第2步 基线 Baseline   → 测试纪律硬闸门（reference/testing-protocol.md）
第3步 四道工序 Passes → 表层清零 → 死代码 → 原则体检 → 链路优化
第4步 对抗自查        → 七视角红队（reference/adversarial-review.md）
第5步 优化报告        → 固定模板交付
```

用户点名只做一部分时（如"只清死代码"），跳过无关工序，但**第 0/1/2/4/5 步永远保留**——侦察定档是前提，基线和自查是闸门，闸门不可跳。

---

## 第 0 步：侦察

1. 运行 `bash <skill目录>/scripts/recon.sh`（在项目根目录执行），拿到机械侦察结果。
2. 人工补充机械脚本看不到的：读项目根的 `PHILOSOPHY.md` / `AGENTS.md` / `CLAUDE.md` / `CONTRIBUTING.md` / `README.md` 的"不做什么"部分；有 `docs/adr/` 就扫一遍 ADR 标题。
3. **git 工作区不干净 → 停**。报告"存在未提交改动，优化会与之混淆"，等用户处理。绝不把自己的优化混进别人的半成品里。（你自己刚创建、用户知情的新文件除外——如实报告即可。）
4. **CI / 测试能不能跑**：如果测试需要外部资源（数据库、硬件、网络）本机跑不了，如实报告，与用户商量降级方案（见测试纪律的降级路径），不许默默跳过测试继续改。

## 第 1 步：定档（三模式）

依据侦察结果选模式，细则见 `reference/modes.md`：

| 模式 | 判定 | 核心纪律 |
|------|------|----------|
| **A 自有项目** | origin 是使用者自己的仓库，或无 remote 的本地项目 | 个人规范集全量适用；缺 PHILOSOPHY.md 时顺手起草（草稿必须交用户确认，不许直接定稿） |
| **B 上游贡献** | 别人的仓库（fork / clone 的开源项目） | **默认只出体检报告，不动代码**。用户明确要求改时：改动收敛到上游风格，行为变更类先 issue 问 intended，不往别人仓库写任何哲学文件 |
| **A-greenfield** | 自有项目但还没有 PHILOSOPHY.md | 考古（git log / ADR / README / 现有代码惯用法）→ 起草哲学文件草稿 → 用户确认后落盘，再继续优化 |

模式判断错了比没有模式更糟。拿不准是不是别人的仓库时，按 B 档保守处理。

## 第 2 步：基线（硬闸门）

**先读 `reference/testing-protocol.md` 再动任何代码。** 五条铁律：

1. **基线先行**：动代码前先跑全量测试，记录 通过/失败/跳过 数。基线红 → 停下报告，不许在红基线上优化（分不清谁弄坏的）。
2. **考卷不可涂改**：优化期间禁止修改/删除/跳过既有测试。唯一例外：随死代码一起删除的、且逐条列入报告的测试。
3. **绿以机器为准**：测试结果以被测命令的退出码为准（警惕管道陷阱：`cmd | tail` 后 `$?` 是 tail 的）。禁止无运行就声称通过；禁止"大概是 flaky"式解读（最多重跑一次并如实记录）。
4. **新坑新考题**：修 bug 先写复现测试（红→绿）；优化本身保行为，不需要新测试，但删代码前若该区域无测试覆盖，先补特征化测试钉住行为。
5. **变异抽查**：高危删除/重写后，临时注入一个故意破坏，确认测试变红再还原。全绿说明该区域无看护 → 如实报告覆盖缺口。

项目无测试时的降级路径也在 `reference/testing-protocol.md` 里，核心是：**没有安全网就不许做不保行为的改动，且报告必须以最显眼的方式声明"本次优化无测试护栏"**。

考卷质量与测试方法工具箱（变异测试打分 / AI 生成测试三大病评审清单 / 性质测试 / LLM evals）→ `reference/testing-techniques.md`，按需加载，不改变五铁律的强制地位。

## 第 3 步：四道工序

每道工序独立成可回滚的小步，做完一道跑一次全量测试再进下一道。

### Pass 1 表层清零（机械，工具说了算）
跑项目自带的 linter / formatter / typecheck（侦察脚本已探测），清到零警告。只修表层，不做语义改动。项目没配工具 → 报告并建议（上游模式只建议不装）。

### Pass 2 死代码清理（证据裁决）
判定标准见 `reference/dead-code-evidence.md`。核心：**一个符号只有过全链证据链才允许删**（全仓搜索 → 动态调用排查 → 公共 API 边界判断 → 框架魔法排查）。小批量删（每批 ≤10 个文件或 ≤200 行），每批之间跑测试。删除清单全部进报告，保证可整体回滚。注释掉的代码、永不启用的 feature flag、未使用的依赖，同属此工序。

### Pass 3 设计原则体检（先报告后动手）
对照 PHILOSOPHY.md（没有则对照内嵌十条军规，或 `REFINERY_NORMS_PATH` 指定的个人规范集）做体检：单一职责、依赖倒置、开闭、高内聚低耦合。产出分级发现清单（P0 违反哲学/P1 明确收益/P2 见仁见智）。**默认只修 P0/P1，P2 只报告**。遇到"有意识的偏离"（代码注释、ADR 里写明为什么违反规范）→ 尊重它，跳过并记录。

### Pass 4 链路优化（证据驱动）
找冗余 I/O、N+1、同步阻塞异步、重复计算、无谓序列化。铁律：**没有测量或明显的算法级问题，就不优化**——性能猜测是范围蔓延的头号来源。改前改后给数字（能测的话），测不了就标"理论推断"。

## 第 4 步：对抗自查

按 `reference/adversarial-review.md` 七视角过一遍自己的 diff：行为不变量 / 考卷完整性 / 死代码误判 / 范围蔓延 / 风格一致性 / 性能回退 / 可回滚性。发现任何一项不干净，回到对应工序修，不许带病交付。大改动（>300 行或跨模块）时把七视角逐条写进报告。

## 第 5 步：优化报告（固定模板）

```markdown
# Refinery 优化报告 — <项目名>
- 模式：A 自有 / B 上游 / A-greenfield（本次顺带起草了 PHILOSOPHY.md 草稿）
- 执行的工序：Pass1 ✅ / Pass2 ✅ / Pass3 报告+修复 / Pass4 跳过（原因）

## 基线证据
- 测试命令：`<命令>`
- 基线：N passed / M failed / K skipped → 终态：N' passed / 0 failed
- lint：`<命令>` 基线 X 警告 → 终态 0

## 改动清单
| # | 工序 | 改了什么 | 为什么 | 证据 |
（死代码删除逐条列出；每条附搜索证据摘要）

## 发现但未动（含原因）
（P2 项、上游模式下只报告项、有意识偏离项、无测试区域）

## 测试纪律执行记录
（基线红绿、变异抽查结果、是否发生测试变更及逐条理由）

## 红队结论
（七视角逐条 pass/fail）
```

## 与其他 Agent 技能的协作（可选，没有也完全可用）

- 纯前端 UI 打磨 → 交给专门的 UI 技能（refinery 不碰视觉）；
- 需要先把"质量红线"写成 CONSTRAINTS.md 并长期看守 → constraint-driven-development 类技能（refinery 读它、遵守它，不重复建）；
- 单纯"读起来费劲"的行为不变重构 → `code-simplification` 五原则作补充参考；
- 性能专题深挖 → Pass 4 发现问题后移交 performance 类技能。

## 深层规范（按需加载，不整包进上下文）

### 内嵌总纲：十条军规（无外部依赖时的标尺）

1. **简单优先**：先做对，再做快；能简单就不要聪明（KISS）。
2. **契约先行**：API 与数据模型先定契约再并行开发。
3. **高内聚低耦合**：模块按业务能力划分，依赖单向、无环。
4. **面向接口**：依赖抽象，实现可替换。
5. **一切皆可回滚**：发布、迁移、配置变更必须有回退方案。
6. **不信任任何输入**：外部输入一律校验；外部调用一律设超时、重试、兜底。
7. **测试是设计工具**：不可测的代码就是设计不好的代码。
8. **可观测内建**：没有日志/指标/追踪的系统等于盲飞。
9. **安全左移**：安全不是上线前的检查项，而是编码时的习惯。
10. **决策留痕**：重要技术决策写 ADR。

裁剪原则：规范服务于交付，不是教条；违反规范需说明理由——"有意识的偏离"优于"无意识的不合规"。

### 接入你自己的规范集（可选）

有成文的工程规范集时，设环境变量 `REFINERY_NORMS_PATH` 指向其目录，Pass 3 体检按需读取对应篇章，优先级高于十条军规：

| 体检需要 | 优先读 |
|---|---|
| SOLID / 设计模式 / 反模式 | 设计原则篇 |
| 分层与模块划分 | 架构篇 |
| 命名 / 函数 / 注释 / 错误处理 / 坏味道 | 编码篇 |
| 测试金字塔 / mock 纪律 / 覆盖率 | 测试篇 |
| 改到输入、认证相关代码时 | 安全编码篇 |
| 各场景检查单 | 检查单附录 |

未设置时：十条军规 + 各 reference 文件内嵌的检查单即为标尺。
