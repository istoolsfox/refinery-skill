# AI 代码验收清单（一页版）

> 来源：《代码整洁之道》（Robert C. Martin，韩磊译，2009）第 2/3/4/7/9/17 章提炼，
> 叠加 AI 生成代码的特有病（实战补录）。定位是**验收标尺**，不是写作教材：
> 验收时逐节过，任何一条不过就打回；通用判据与 AI 特有病分开列。

## 一、命名

- [ ] **名副其实**：不看实现就能答出"它是什么、干什么"；需要注释解释的名字 = 名字失败。
- [ ] **不误导**：名字承诺的行为与真实行为一致（叫 `get_users` 的别顺手写库，`list` 变量别装的不是列表）。
- [ ] **有区分度**：`data1`/`info2`/`xxxFlag` 式纯编号或空泛区分直接打回；区分靠语义，不靠编号。
- [ ] **可搜索**：魔法数字、重复字面量提为命名常量；名字宁可长，也要搜得到。
- [ ] **一概念一词**：同一角色全程一个动词（都叫 `fetch` 或都叫 `get`），混用即打回。
- [ ] **无双关**：同一函数名不承担第二种语义；要承担就拆成两个名字。

## 二、函数

- [ ] **只做一件事**：函数名说不清它在干什么 = 它干了不止一件事，拆。
- [ ] **一个抽象层级**：同一函数内不混"高层编排"与"底层细节"。
- [ ] **参数克制**：3 个以上要停一停；布尔开关参数改成两个函数或选项对象。
- [ ] **无副作用**：名说 check 的不写入，名说 parse 的不发请求；名实一致。
- [ ] **指令与询问分离**：函数要么做事要么回答问题，不做"查询成功就顺手改状态"。
- [ ] **错误处理不污染主线**：try-catch 抽成独立边界函数，主逻辑保持一条直线。

## 三、注释

- [ ] **先改代码再想注释**：改名/拆函数能消除的注释，改代码而不是留注释。
- [ ] **解释为什么，不复述是什么**：复述代码的注释是废话，删。
- [ ] **注释掉的代码删干净**：版本控制管历史，注释里不留尸体。
- [ ] **日志式/署名式注释删干净**：`git log`/`git blame` 管历史。
- [ ] **TODO 必须带上下文**：谁、为什么、什么时候处理；三缺一就删。
- [ ] **AI 特有病——总结腔注释**：`// 下面这行是……` 式逐行解说、文件头注释复读函数签名，逐条清。

## 四、错误处理

- [ ] **不返回 null，不传 null**：用空集合/空对象/结果类型表达"没有"。
- [ ] **异常带环境信息**：catch 后再抛，带上"当时在干什么"；禁止裸吞或裸 re-raise。
- [ ] **先定边界再写逻辑**：先写 try-catch 钉住失败出口，再填业务。
- [ ] **不用错误码/魔法负数当状态**：用异常或结果类型，状态判断不靠猜数字。

## 五、测试（F.I.R.S.T）

- [ ] **Fast**：单元测试秒级完成。
- [ ] **Independent**：测试间互不依赖，顺序打乱结果不变。
- [ ] **Repeatable**：任何机器任何时间结果一致（不碰真实网络/时钟/随机数）。
- [ ] **Self-validating**：通过/失败二值，不靠肉眼比对。
- [ ] **Timely**：测试随被测代码一起交付，不留"以后补"。

## 六、坏味道速查（抽查高频项）

- [ ] **重复代码**：两处以上相似逻辑提函数（D.R.Y.）。
- [ ] **过深嵌套**：超过 2 层考虑卫语句早退，主逻辑少缩进。
- [ ] **万能类**：说不出"这个类为什么存在、什么改动会碰它"的类，拆。
- [ ] **夸夸其谈的通用性**：当前用不到的抽象、参数、扩展点删掉（YAGNI）。
- [ ] **AI 特有病——幻觉调用**：调用了不存在的 API/参数，运行即炸；typecheck 必须过。
- [ ] **AI 特有病——占位实现**：函数体是 `pass`/`TODO`/写死返回值，调用方却当真数据用；逐个函数追问"真干了吗"。
- [ ] **AI 特有病——过度防御**：不可能为 null 的地方判 null、不可能失败的调用包 try，删。
- [ ] **AI 特有病——超长函数**：AI 爱一口气写百行函数，对照"只做一件事"拆。

## 带滤镜的两条（不是教条）

1. **别照搬"超短函数"的数字**：原著主张函数二十行封顶；现代共识是"一个抽象层级"比行数重要，
   硬拆会把逻辑切成跳来跳去的碎片。
2. **注释教条重新掂量**：AI 时代给 Agent 交代需求的注释、给 reviewer 的上下文注释是有效沟通；
   该删的是复述代码的废话，不是一切注释。

## 打回话术模板

> 第 X 节第 N 条不过：`<文件:行号>` <一句话说明问题>；建议改法：<具体动作>。

验收纪律与零号铁律同源：**打回必须点名条目和位置，不许凭感觉说"代码味道不对"。**
