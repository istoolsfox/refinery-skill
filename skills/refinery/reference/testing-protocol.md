# Refinery 测试纪律（硬闸门）

> 为什么需要这一页：AI 自己"测一下"是不可控的——会顺手改断言、跳过失败用例、放宽阈值来变绿，
> 会把"目测应该没问题"当成"已验证"。本页把测试变成机器裁决的闸门，AI 只有执行权，没有裁决权。
> 理论底座："测试是设计工具而非验收仪式"（作者工程规范）、Feathers《Working Effectively with
> Legacy Code》的特征化测试（characterization test）、变异测试思想（测试没机会变红 = 没有看护）。

## 五条铁律

### 铁律 1：基线先行（Baseline First）

动任何代码**之前**，跑项目全量测试套件，记录三个数：passed / failed / skipped。

- 基线全绿 → 正常开工。
- 基线有红 → **停**。先报告失败详情，与用户确认是否为已知问题；未经确认不得开工——在红基线上优化，你无法区分"我改坏的"和"本来就坏的"。
- 基线有 skip → 记录数量；优化结束时 skip 数不得增加（增加 = 你在跳过东西，违规）。
- lint/typecheck 同样先跑一遍记录基线数字，终态对比。

### 铁律 2：考卷不可涂改（Tests Are the Contract）

优化期间，既有测试 = 用户签收过的行为契约：

- **禁止**：修改断言、删除测试、加 skip/xfail、放宽容差或超时、注释掉失败用例、降低覆盖率阈值。
- **唯一例外**：Pass 2 死代码清理中，被删死代码专属的测试随之删除，且必须逐条列进报告（测试名 + 对应死代码），接受红队"考卷完整性"视角复核。
- **发现测试本身写错了**（测的是错误行为、断言与文档矛盾）→ **停**，报告证据，等用户裁决。AI 无权判定"考题出错了"然后顺手改——这正是不可控的根源。
- 项目有 `CONSTRAINTS.md`（质量红线类文件）→ 它是更高优先级的契约，diff 中任何触碰它的行都要在报告里单独说明。

### 铁律 3：绿以机器为准（Machine Is the Judge）

- 每次声称"通过"，报告里必须有可复查的命令行 + **被测命令自身**的退出码。没有运行就没有发言权。
- **管道陷阱**：`cmd | tail` 之后 `$?` 取的是 tail 的退出码——这是真实踩过的坑（假基线 exit=0 被复跑抓出）。用 `set -o pipefail`、`PIPESTATUS` 或直接不接管道。
- 失败一律先怀疑自己的改动（你 99% 是嫌疑人）。判定"与本次无关"需要证据：错误在基线中已存在（对照铁律 1 的基线输出）。
- 疑似 flaky：最多重跑一次，两次结果不一致 → 如实报告为 flaky 并给出两次输出，不许重跑到绿为止。Silent retry-until-green 是造假。

### 铁律 4：新坑新考题（New Behavior, New Test）

- 行为保持的重构（本 skill 的主场景）：不需要新测试，既有套件全绿就是证明。
- 顺带修 bug：**先写失败测试**（复现考题，红）→ 修（绿）。没有复现测试的修复 = 没修。
- 删除/重写某段代码前，若该区域测试覆盖为零：先补**特征化测试**——不管代码"应该"怎样，先钉住它"现在"怎样（输入→输出快照、golden master），让重构有安全网，然后再动。

### 铁律 5：变异抽查（Mutation Spot-Check）

高危操作之后（删除 >50 行、重写核心函数、合并重复分支），做一次手工变异测试：

1. 在刚改过的代码里注入一个故意破坏（改一个边界值、删一个检查、返回错值）；
2. 跑测试，确认相关测试变红；
3. 还原注入，确认回到绿。

- 变红 → 该区域有看护，放心。
- 全绿 → 该区域**没有看护**，你刚才的改动不被任何测试保护。两个选择：补特征化测试后再继续（推荐），或回滚该处改动并在报告里声明"此处无测试护栏，未动"。

## 降级路径（项目没有测试 / 测试跑不起来）

按顺序尝试，全部失败才允许"无护栏静态模式"，且报告首页必须用 `⚠️ 无测试护栏` 醒目声明：

1. 探测其他测试入口（`make test`、`scripts/check.sh`、CI 配置里的命令、`tox`/`nox`、语言框架默认目录 `test/` `tests/` `__tests__/` `*_test.dart`）。
2. 测试需要外部资源（DB/硬件/网络）本机跑不了 → 只跑能跑的子集，报告里写明跳过了什么、为什么。
3. 完全无测试：
   - 只做**可静态证明安全**的优化（表层清零、编译器/类型系统兜底的改名与删除）；
   - 对要动的核心路径先补特征化测试（铁律 4），把安全网织出来再动；
   - 保行为红线升级为：除静态可证明项外一律不动，发现清单全部进"发现但未动"。

## 与流程的耦合

- 第 2 步（基线）执行铁律 1；每道工序之间执行铁律 2/3；铁律 4/5 按场景触发。
- 对抗自查的"考卷完整性"视角 = 对铁律 2 的红队复核；报告模板的"测试纪律执行记录"节 = 逐条留痕。
- 上游贡献模式额外纪律：跑上游自己的测试命令（看 CONTRIBUTING）；测试风格跟着上游走；**永不**在别人的仓库里补你自己的测试框架。
