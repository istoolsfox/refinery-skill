# 死代码判定证据标准（Pass 2 专用）

> 死代码清理是 AI 优化里最容易"自信翻车"的工序：删一个"看起来没人用"的东西，
> 炸掉反射调用、框架魔法或另一个仓库的引用。本页定义唯一的放行标准：**证据链完整才许删**。
> 零号铁律在此处最致命——"没人用"是一个断言，断言就要有证据。

## 什么算死代码（目标清单）

1. 全仓零引用的函数/类/变量/常量/导出；
2. 注释掉的代码块（>10 行或成段的旧实现）；
3. 永远为 false 的 feature flag 及其死分支（要证据：默认值 + 全仓无赋值点）；
4. 未使用的依赖（package.json/pubspec.yaml/go.mod/requirements.txt 里声明但零 import）；
5. 未使用的资源（图片/字体/翻译键，零引用）;
6. 调试残留（console.log / print / TODO-废弃 / 被绕过的旧函数）。

## 放行证据链（四步，全部通过才许删）

### 第 1 步：全仓搜索
- 符号名的精确搜索（带词边界），覆盖**所有文件类型**：源码、模板、配置（yaml/toml/json）、
  文档、脚本、`.github/` workflows、Dockerfile——CI 脚本里的调用最常被漏掉。
- 搜的不是"精确同名"就完事：部分匹配（前缀/后缀）也扫一眼，防动态拼接调用名。

### 第 2 步：动态调用排查（按语言过清单）

| 语言/生态 | 陷阱 |
|---|---|
| Python | `getattr(obj, name)` 字符串调用、`__getattr__`、装饰器注册、`importlib`、入口点（console_scripts）、`__all__` 外的隐式导出 |
| Dart/Flutter | 反射少但注意 `MethodChannel` 字符串协议、代码生成目标（`@JsonSerializable` 等注解引用）、`part`/`export` 链 |
| JS/TS | 动态 `obj[key]`、字符串路由、`require(变量)`、框架按文件名约定加载（Next/Nuxt 页面）、side-effect import |
| Go | `interface{}` 断言、`reflect`、`init()` 副作用、构建标签 `//go:build` 下的代码 |
| Rust | `#[cfg]` 特性开关、宏生成的调用、`trait` 动态分发 |
| C/C++/ObjC | 宏拼接、`dlsym`、协议/selector 字符串、export 符号表 |

搜不到直接调用 ≠ 没人调用。第 2 步的目标是排除"间接的、字符串形式的、约定式的"调用。

### 第 3 步：公共 API 边界判断
- **库/SDK/被别人 import 的包**：导出的符号即使仓内零引用也不是死代码——使用者在外部。
  只有废弃流程（deprecate → 标记 → 下个大版本删）或维护者明确允许时才动。
- **应用/服务（终产物）**：导出符号无人用 = 死代码，可删。
- 判定依据：包管理清单的发布配置（`publish_to` 等）、README 是否说"这是个库"、
  是否被其他项目引用。

### 第 4 步：框架魔法排查
路由表按字符串注册？ORM 按约定映射？CLI 按函数名分发？测试 fixture 按命名约定收集？
查框架文档确认加载机制，再下结论。

## 删除操作纪律

- **小批量**：每批 ≤10 个文件或 ≤200 行（取小者），批间全量测试（测试纪律铁律 3）；
- **先删叶子**：先删无依赖的，再删"只被死代码引用"的连锁死代码（删完一批可能解锁新一批，重新过证据链）；
- **变异抽查**：高危删除后按测试纪律铁律 5 注入验证；
- **报告可回滚**：删除清单逐条列文件+符号+证据摘要，保证一次 revert 能整体还原；
- **依赖删除**：先删代码里的 import/引用，再跑一遍构建确认，最后才从清单文件移除依赖声明。

## 不许删清单（直接跳过，最多报告）

- 上游贡献模式下的公共 API（除非维护者邀请）；
- 带有"保留原因"注释的代码（`# noqa`、`// Keep:`、兼容层标记）——先读注释再判断；
- 版本兼容分支（`if legacy:` 类）——通常服务老客户端，删除是行为变更；
- 看不懂的代码：**看不懂 = 不是死代码**（你还不够格判定它死），进"发现但未动"。

## 工具辅助（有就用，没证据力不替代人工）

Python：`vulture`（置信度报告，仍需人工过证据链）、`ruff --select F401,F841`；
JS/TS：`knip`、`ts-prune`；Go：`staticcheck -checks U1000`；
Dart：`dart analyze` 的 unused 提示 + `dart fix --apply`。
工具输出只是**候选名单**，每一条仍要走四步证据链——工具会把动态调用误报为死代码。
