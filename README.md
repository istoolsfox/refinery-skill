# refinery（精炼厂）

**一句话触发的全项目代码优化引擎**——一个面向 AI 编码 Agent 的 Skill（Agent Skill 格式）。

在任何项目里说一句"优化一下这个项目"或"清理死代码"，Agent 就会走完一条带闸门的流水线：
**侦察 → 定档 → 基线 → 四道工序 → 对抗自查 → 优化报告**。

## 为什么需要它

AI 优化代码有两个致命的不可控：

1. **测试作弊**：AI 自己测自己，会顺手改断言、跳过失败用例、放宽阈值来"变绿"，把"目测应该没问题"当成"已验证"；
2. **风格入侵**：AI 把自己的偏好强加给项目——在别人的开源仓库里发动风格战争，在成熟项目里乱改惯用法。

refinery 的答案不是"提醒 AI 注意"，而是**把规范变成带闸门的流程**：AI 只有执行权，没有裁决权。

## 核心设计

| 机制 | 防的是什么 |
|---|---|
| **测试纪律五铁律**（硬闸门） | 测试作弊：基线先行 / 考卷不可涂改 / 绿以机器为准 / 新坑新考题 / 变异抽查 |
| **三模式定档** | 风格入侵：自有项目全量规范；**别人的仓库默认只出报告不动代码**；要改则收敛上游风格 |
| **死代码四步证据链** | 自信误删：全仓搜索 → 动态调用排查 → 公共 API 边界 → 框架魔法，全过才许删 |
| **七视角对抗自查** | 自我说服：行为不变量/考卷完整性/死代码误判/范围蔓延/风格一致性/性能回退/可回滚性 |
| **零号铁律** | 幻觉：说"没人用"必须有搜索证据，说"测试通过"必须贴退出码，拿不准标"未确认" |
| **PHILOSOPHY.md 哲学文件** | 项目没有宪法：每项目一份五段式哲学文件（宗旨/设计哲学/风格三层/禁区/机器命令），Agent 帮你起草、你拍板 |

一个值得说的细节：**铁律 3 的"管道陷阱"条款来自真实事故**——AI 在管道里跑 `flutter test | tail` 后取 `$?`，拿到的是 tail 的退出码，得到假基线 exit=0，被复跑抓出。AI 也会犯它要防的错，所以裁决权必须从 AI 手里拿走。

## 快速开始

把 `refinery/` 整个目录拷进你的 Agent 技能目录即可（以 `~/.agents/skills/` 为例）：

```bash
git clone https://github.com/istoolsfox/refinery-skill.git
cp -r refinery-skill/refinery ~/.agents/skills/
```

然后在对项目说话时用触发词即可：**优化代码 / 清理死代码 / 代码体检 / 精炼 / 重构 / optimize / refactor / clean up dead code**。

### 可选配置

| 环境变量 | 作用 |
|---|---|
| `REFINERY_OWN_USER` | 你的 GitHub 用户名。recon 用于自动判定"自有项目 / 上游贡献"模式；不设则回退读 `git config github.user`，都没有时按上游模式保守处理 |
| `REFINERY_NORMS_PATH` | 指向你自己的工程规范集目录（Markdown 集合即可）。Pass 3 体检按需读取对应篇章；不设则用内嵌的"十条军规"当标尺 |

## 三种场景

| 场景 | 行为 |
|---|---|
| 自己的项目，有哲学文件 | 全量优化，PHILOSOPHY.md 优先于通用规范 |
| 自己的项目，没有哲学文件 | 考古（git log/ADR/README/代码惯用法）→ 起草 PHILOSOPHY.md 草稿 → **你确认后**才动工 |
| 别人的仓库（fork/开源克隆） | **默认只出体检报告，一行代码不动**；明确要改时：风格三层收敛 + 行为变更先 issue 问 intended + 改完不 push 等你审 |

## 目录结构

```
refinery/
├── SKILL.md                        # 六步流水线主流程 + 内嵌十条军规
└── reference/
    ├── testing-protocol.md         # ★ 测试纪律五铁律（硬闸门）+ 无测试降级路径
    ├── testing-techniques.md       # 测试方法工具箱：变异测试工具矩阵/AI 测试三大病/性质测试/LLM evals
    ├── modes.md                    # 三模式细则 + 上游考古方法
    ├── dead-code-evidence.md       # 死代码四步证据链（按语言的动态调用陷阱清单）
    ├── adversarial-review.md       # 七视角红队 + 优化报告固定模板
    └── philosophy-template.md      # PHILOSOPHY.md 模板 + 提炼方法
└── scripts/
    └── recon.sh                    # 机械侦察：git 身份/哲学文件/技术栈/测试命令（只读）
```

## 设计来源

- Michael Feathers《Working Effectively with Legacy Code》——特征化测试与安全网思想；
- 变异测试 / CRAP 思想——"测试没机会变红 = 没有看护"；
- LLM 应用 evals 方法论——binary 断言优于打分、error discovery 优先；
- 作者多年开源贡献实战（上游风格考古、行为变更先问 intended、PR 纪律）；
- 十条军规与"有意识的偏离优于无意识的不合规"裁剪原则，来自作者的个人工程规范集。

## 实战验证

首发前在作者的一个 Flutter 三端项目（61 源文件 / 180 测试 / 双 agent 审计过的 v0.1.0）完成端到端验证：全流程跑通、闸门真实拦截（抓出并修复了 AI 自己的假基线）、诚实交付"零代码可优化项"结论，并在过程中抓到两个环境可复现性缺陷回写项目文档。
